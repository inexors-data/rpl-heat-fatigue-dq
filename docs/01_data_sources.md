# Проверка источников данных

Проект: «Жара, перелёты и возраст в РПЛ» + DQ-пайплайн
Дата проверки: 2026-10-22

## Итог в одном абзаце

Публичных **поматчевых физических данных** (пробег, спринты) по РПЛ нет. Яндекс Спорттех собирает их с сезона 2023/24, но наружу отдаёт только трансляции и сезонные отчёты лиги. Портал yandex.ru/sport закрыт. Поэтому целевая переменная проекта — **поведенческие прокси усталости** из event-данных: доля xG и ударов в концовке, падение интенсивности атаки после 60/75-й минуты, время замен. Всё остальное (календарь, составы, минуты, возраст, стадионы с координатами, погода, xG по ударам) доступно бесплатно и в машиночитаемом виде.

## Что уже нашлось по качеству данных

Это и есть материал для DQ-слоя и README.

1. **Ложная метка часового пояса в API РПЛ.** Поле `date` выглядит как `2025-07-18UTC20:30:00`, но это **московское время**. У Understat тот же матч «Динамо» — «Балтика» стоит на `2025-07-18 17:30:00` UTC. Если поверить метке, погода берётся на 3 часа позже: по Open-Meteo это 19,7°C вместо 23,4°C, ошибка 3,7°C на одном только летнем вечернем матче. В пайплайне нужна явная нормализация `Europe/Moscow → UTC` и тест «время начала совпадает с Understat ± 15 мин».
2. **Нестандартный формат дат.** В API РПЛ встречается и `2025-07-18UTC20:30:00`, и `2025-07-18 20:30:00` (в `getPlayerGamesStats`). Даты рождения тоже идут с меткой `UTC00:00:00`.
3. **Сопоставление команд между источниками.** В РПЛ два разных клуба «Динамо»: московское (Understat id 190, `Dinamo Moscow`) и махачкалинское (Understat id 284, `Dynamo Makhachkala`, в РПЛ с 2024/25). Это не ошибка в данных, а ловушка для сопоставления. Understat транслитерирует их по-разному (Dinamo/Dynamo), поэтому наивная нормализация вроде «Dinamo → Dynamo» с нечётким поиском по слову «Динамо» может склеить два клуба или привязать матч не к тому. Кроме того, у Understat префиксы `FK Akhmat`, `FC Rostov`, `PFC Sochi`, а у API РПЛ — `Динамо-Москва`, `Динамо Махачкала`, `ПФК ЦСКА`. Решение: сопоставлять только по id через ручную таблицу соответствий `dim_team_xref` (id РПЛ ↔ id Understat, без сравнения строк) и тесты «все 16 команд сезона сопоставлены» и «соответствие один к одному: один id Understat → ровно один id РПЛ».
4. **Сопоставление игроков.** У РПЛ кириллица и транслит-ключ (`Lunev-Andrei`, `Skopincev-Dmitrii`), у Understat англоязычное имя (`Andrey Lunev`). Легионеры идут под никами (`Битело` = `de Souza Mares Zhoao Paulo`). План: матч по (команда, матч, минуты на поле) + нечёткое сравнение имён, с отчётом о несопоставленных.
5. **Стадион клуба ≠ стадион матча.** `getClubStadium` отдаёт текущий домашний стадион, а матчи переносятся: в 2025/26 в списке городов есть Саранск, которого нет ни у одного клуба. «Акрон» (Тольятти) и «Крылья Советов» играют на одном стадионе в Самаре. Координаты для погоды и перелётов брать по `match.stadium`, справочник стадионов вести отдельно.
6. **Пустая статистика текущего сезона.** Для 2026/27 `getGameStatistics` возвращает `{"match": []}`. Это нужно проверять на полноту, а не молча загружать нули.
7. **Технические поражения.** В событиях есть `htmlCustomEvent` «Техническое поражение»: счёт в протоколе ≠ счёту на поле. Такие матчи нужно помечать флагом и исключать из анализа игры.

## Что это значит для исследовательского вопроса

- **Разброс условий хороший.** Калининград (UTC+2), Москва/Петербург/Казань/юг (UTC+3), Самара (UTC+4), Оренбург и Екатеринбург в 2023/24 (UTC+5). Перелёты до ~2 900 км (Калининград — Грозный), летние матчи под +30°C на юге и поздние осенние около нуля.
- **Объём:** 3 сезона × 240 матчей = **720 матчей**, ~30 000 записей «игрок — матч». Для смешанной модели достаточно; для узких срезов (возраст 33+ × жара) — впритык, это нужно честно указать.
- **Целевые переменные (прокси):** xG и удары за 75–90′ относительно 0–60′; разница xG команды по отрезкам; минута первой замены; доля игроков 30+, отыгравших 90 минут.
- **Факторы:** температура, ощущаемая температура, влажность на время начала; расстояние перелёта, смена часовых поясов, дни отдыха после прошлого матча (включая Кубок России — его тоже нужно загрузить, иначе дни отдыха будут завышены); средний возраст стартового состава, возраст игрока, амплуа.

## Ограничение, которое честно пишем в README

На открытых данных нельзя измерить реальную физику и состояние игрока до матча (GPS, wellness, тренировочную нагрузку). Проект показывает пайплайн и методологию; в клубе тот же каркас подключается к внутреннему GPS-контуру, и прокси заменяются реальным пробегом и высокоинтенсивной работой.

## Окружение

- В этой сети `curl` (schannel) падает с `CRYPT_E_NO_REVOCATION_CHECK`; помогает `--ssl-no-revoke`. Python `requests` использует свой certifi, так что пайплайн это не затрагивает.
- Python 3.12.10 установлен.
